# Щотижневий ритуал: адаптований тиждень із даних

Це «жива» частина плану. Раз на тиждень (найкраще — понеділок зранку) ти
запускаєш ритуал, він дивиться на реальні дані минулого тижня — **навантаження**
(Strava) і **відновлення** (Garmin) — і пише `week.json` для наступного тижня.
Сторінка сама його показує з бейджем «адаптовано».

---

## ⚠️ Де це запускається

| Джерело | Тип конектора | Де працює |
|---|---|---|
| **Strava** | офіційний, хостований MCP | будь-де: Claude на вебі, десктоп, Claude Code |
| **Garmin** | **неофіційний, локальний** | **тільки локально** — Claude Code / Claude Desktop на твоїй машині |

Через Garmin **повний ритуал запускається локально**, у Claude Code на твоєму
комп'ютері, де підключені обидва конектори. У хмарній веб-сесії Garmin недоступний
(потрібен твій логін + MFA, а токени мають лишатись у тебе). Без Garmin ритуал
теж працює — просто на самому навантаженні зі Strava, і позначає це у flags.

---

## Одноразове налаштування Garmin (на твоїй машині)

Офіційного хостованого Garmin-конектора немає (їхня dev-програма — для компаній і
на паузі). Використовуємо неофіційний local-first конектор
[davidmosiah/garmin-mcp](https://github.com/davidmosiah/garmin-mcp) (npm-пакет
`garmin-mcp-unofficial`). Усе виконується **на твоїй машині**.

**1. Авторизація (питає email/пароль/MFA локально):**
```bash
npx -y garmin-mcp-unofficial auth
```
Пароль не зберігається — лише короткоживучі токени у `~/.garmin-mcp/garmin_tokens.json`
(права лише для тебе). MFA-код вводиш зі свого телефона. Логінься рідко — часті
headless-логіни провокують тротлінг.

**2. Перевірка:**
```bash
npx -y garmin-mcp-unofficial doctor
```

**3. Додати як MCP-сервер у локальний Claude Code** (у корені репо):
```bash
claude mcp add garmin -- npx -y garmin-mcp-unofficial
```
або вручну в конфіг MCP-клієнта:
```json
{
  "mcpServers": {
    "garmin": { "command": "npx", "args": ["-y", "garmin-mcp-unofficial"] }
  }
}
```
Після цього поряд зі Strava з'являться інструменти `garmin_connection_status`,
`garmin_daily_summary`, `garmin_weekly_summary` та ін. (readiness, HRV, сон,
Body Battery, activities). У `/plan-week` вони вже прописані в `allowed-tools`.

> **Не додавай цей сервер у репо через `.mcp.json`** — інакше хмарна веб-сесія теж
> намагатиметься його запустити (і зависне без авторизації). Garmin — суто локальний.

**Чесні застереження:** це неофіційний доступ (сіра зона ToS Garmin), він крихкий
(може зламатись, якщо Garmin змінить ендпоінти) і потребує локального запуску.
Логінься рідко — часті headless-логіни провокують тротлінг.

Модель у нас **Epix 2 (Gen 2)** — має повний набір: Training Readiness (готовий
композитний скор), HRV Status, Sleep Score, Body Battery, Recovery Time, Training
Load. Тобто «готовність» не треба перевинаходити — беремо готовий скор Garmin.

## Як запускати

У локальному Claude Code в корені репо:

```
/plan-week            # поточний/наступний тиждень
/plan-week 3          # конкретний номер тижня
```

Команда:
1. читає `js/plan.js` (скелет плану) і визначає цільовий тиждень;
2. тягне навантаження зі Strava (обсяг, довгий, пульсові стріми → % часу в
   розмовній зоні);
3. тягне відновлення з Garmin (readiness, HRV-тренд, сон, Body Battery) — якщо
   конектор підключено;
4. рахує вердикт (таблиця нижче), пише `week.json`;
5. показує тобі вердикт + обґрунтування, і **після твого «так»** комітить і пушить.

Далі — 1–2 хвилини, і сайт оновлений.

## Логіка вердикту (дорадчо, не догма)

Спершу оцінюємо два боки окремо, тоді зводимо.

**Відновлення (Garmin) — світлофор:**

| | Training Readiness (7 дн) | HRV Status | Сон (сер.) | Body Battery |
|---|---|---|---|---|
| 🟢 зелений | ≥ ~65 | balanced | ≥ ~7 год | відновлюється за ніч (ранковий max ≥ ~70) |
| 🟡 жовтий | 45–65 | інколи unbalanced | 6–7 год | частково |
| 🔴 червоний | < 45 кілька днів | low / стабільно unbalanced | < 6 год | не відновлюється |

**Навантаження (Strava) — чи був останній довгий «контрольований»:**
- ✅ так: ≥ ~60% часу ≤140 (розмовна зона), завершений як планувалось, без «вмирання» в кінці;
- ❌ ні: багато часу в Z3+, недокатаний, важкий.

**Зведення → вердикт:**

| Відновлення | Останній довгий | Вердикт |
|---|---|---|
| 🔴 червоний | будь-що | **deload** — повтори або зменш довгий, тримай обсяг |
| 🟢 зелений | ✅ контрольований | **step-up** — плановий крок угору |
| решта (🟡, або 🟢+❌) | — | **hold** — та сама дистанція довгого, що минулого тижня |

Правило кроку вгору з основного плану: нарощуй, **тільки якщо «міг би ще»**, не
героїчно. Розвантажувальні тижні (4, 8, 10) не пропускаємо навіть при зеленому
відновленні — форма росте на відновленні.

## `week.json` — схема

```jsonc
{
  "generatedAt": "2026-08-17",         // дата генерації
  "weekNumber": 5,                      // номер тижня з js/plan.js
  "verdict": "step-up",                 // step-up | hold | deload
  "coachNote": "…",                     // 2–4 речення, конкретно, з цифрами
  "rides": [                            // адаптовані виїзди тижня
    { "type": "long",  "km": 100, "hrZone": "≤140 · перші 2/3", "note": "…" },
    { "type": "mid",   "km": 55,  "note": "рівно" },
    { "type": "short", "km": 30 }
  ],
  "basedOn": {
    "strava": { "lastWeekKm": 130, "longRideKm": 115, "avgHrLong": 138, "formTrend": "up" },
    "garmin": { "trainingReadiness": 72, "hrvStatus": "balanced", "sleepAvgH": 7.4, "bodyBatteryLow": 26 }
  },
  "flags": ["…"]                        // короткі спостереження / застереження
}
```

Правила: числа **тільки з даних**, не вигадувати. Чого нема (напр. Garmin не
підключено) — не підставляти, а позначити у `flags`. Де адаптована дистанція
відрізняється від плану — сторінка сама покаже перекреслене «план N». Поле
`example` для реальних тижнів **не ставити** (воно лише для демо-заглушки).

---

## Якщо Garmin ще не підключено

Ритуал працює на самій Strava: вердикт рахується лише за навантаженням, `basedOn`
містить тільки `strava`, а у `flags` додається «Garmin не підключено — вердикт лише
за навантаженням». Так само коректно; просто «сліпий» до сну/HRV. Саме так
згенеровано перший тиждень (v1).
